# 관리 콘솔

[README](../README.md) 로 돌아가기 · 관련 문서: [API](api.md) · [보안](security.md) · 화면 디자인 규칙: [admin/DESIGN.md](../admin/DESIGN.md)

## 처음 쓸 때

1. 관리자로 로그인한다.
2. `2단계 인증` 메뉴에서 인증 앱을 등록한다 (QR).
3. 로그아웃 후 다시 로그인하면 관리 API 를 쓸 수 있다.

## 동작 방식 (BFF)

Next.js 서버가 OAuth 클라이언트 역할을 한다. 브라우저는 IAM 토큰을 보지 못하고, 토큰은 암호화한 httpOnly 쿠키에만 있다.

- **로그인**: `/auth/login` → IAM `/oauth2/authorize` (PKCE, `iam-admin` public client) → `/callback` 에서 code 교환 → 세션 쿠키
- **API 호출**: 서버 컴포넌트·서버 액션이 `callIam()` 으로 토큰을 붙여 `/api/**` 를 부른다
- **토큰 만료**: IAM 은 public client 에 refresh token 을 주지 않으므로 다시 authorize 로 보낸다. IdP 로그인 세션(8시간)이 살아 있으면 화면 없이 돌아온다
- **로그아웃**: 콘솔 세션 삭제 → IAM `/connect/logout` 으로 IdP 로그인 세션까지 끝낸다
- **접근 제어**: `proxy.ts` 가 세션 쿠키가 없으면 로그인으로 보낸다 (복호화·만료 검증은 서버 코드가 한다)
- **로그인 뒤 돌아갈 곳**: 이 콘솔 안의 경로만 받는다. 다른 사이트로 가는 주소는 홈으로 바꾼다

## 메뉴

왼쪽 메뉴와 화면 영역은 본인 관리 범위(`/me/admin-scope`)에 맞춰 보인다. 조직 단위 관리자에게는 사용자·조직만 보이고, 사용자 상세의 역할·위험 평가·변경 이력처럼 전체 관리자 전용 영역은 숨긴다.

**내 계정**

- 내 정보: 로그인 방법, 보유 역할, 비밀번호 변경 (바꾸면 모든 기기에서 로그아웃)
- 2단계 인증: 인증 앱 목록·삭제·추가 등록, 패스키 목록·삭제
- 내 검토 할 일: 배정된 접근 재검토 항목 유지·회수
- 내 권한 요청: 임시 권한 요청·취소, 내 역할 위임·종료, 비상 접근 시작·종료

**사람과 조직**

- 사용자: 검색, 구분(내부/외부) 필터, 만들기(외부는 이메일·고객사 조직)
  - 상세: 정보 수정, 사용 중지, 퇴사, 로그인 계정(만들기·잠금 해제·비밀번호 초기화), 2단계 인증(분실 시 초기화), 소속(직위·직급·조직 관리자), 역할(만료일 변경), 세션(모두 끊기), API 키(발급·폐기), 위험 평가, 변경 이력
- 조직: 트리, 이동, 수정, 닫기, 구성원, 조직 역할 규칙
- 그룹: 수정, 끄기, 구성원, 그룹 역할 규칙

**권한**

- 역할: 수정, 끄기, 담긴 권한 추가·빼기
- 리소스·권한: 클라이언트별 트리, 수정, 끄기
  - SSO 클라이언트: 등록, 수정(리다이렉트·로그아웃 뒤 주소·scope), 끄기, 비밀값 재발급, 연동 정보
- 범위: 수정, 끄기
- 정책: ABAC 규칙 버전, 활성화, 수정, 대상 바꾸기, 끄기, 예외
- 직무 분리: 심각도·설명 수정, 끄기, 예외

**운영**

- 승인 대기: JIT·비상 접근 요청 승인·반려, 처리 기록
- 비상 접근: 정책 추가·수정·대상 그룹·켜기/끄기, 진행 중인 세션 끝내기
- 위임: 목록, 회수
- 접근 재검토: 캠페인 시작·진행률, 항목 유지·회수, 마감, 증적 CSV
- 위험 정책: 추가, 수정, 켜기/끄기
- HR 연동: 호출 방법, 직원 JSON 미리보기·반영, 최근 실행·오류
- 웹훅: 구독 추가·수정·켜기/끄기, 비밀값 교체, 시험 보내기, 전달 기록·다시 보내기, 서명 검증 방법
- 감사 기록: 기간·대상·유형 검색

**개발자**

- 연동 가이드 (로그인한 사람 누구나): 이 IAM 의 OIDC 주소(복사), 스택별 가이드, 가이드가 가리키는 예제 소스
  - 원본은 `docs/integration/*.md` 이고 콘솔은 그대로 보여 준다 (빌드 때 읽는다)
  - 리소스·권한에서 클라이언트를 고르면 그 클라이언트의 연동 정보(client ID·issuer·discovery)도 보인다

**공통**

- 상단 전역 검색: 사용자·조직·그룹·역할

## 기준 데이터 다루기

기준 데이터(사용자·조직·그룹·역할·리소스·권한·범위·정책·직무 분리·SSO 클라이언트)는 지우지 않고 **수정·끄기/켜기**로 다룬다. 감사 기록과 과거 판정 근거가 이 데이터를 가리키기 때문이다. 역할의 권한, 정책·직무 분리 예외 같은 연결은 회수(기간 종료)한다.

## 코드 위치

- 화면은 `src/app/(console)/` 아래에 둔다 (왼쪽 메뉴·상단 검색이 있는 레이아웃). 로그인 실패처럼 로그인 전 화면은 그 밖에 둔다.
- 화면 데이터는 서버 컴포넌트가 IAM 조회 API 로 읽는다 (`src/lib/queries.ts`).
- 변경은 서버 액션이 처리한 뒤 화면을 갱신한다 (`src/lib/actions.ts`, `src/components/action-form.tsx`).
- 버튼 모양은 `buttonClass`(`src/components/ui.tsx`)를 쓴다.
